# High-cardinality choice extension

The model head already has 265 output slots. The probability-v2 planner now supports purposeful choice-count tiers through 265, while the old broad-v1 catalog remains limited to its original four-choice format. New high-cardinality tasks must use the assigned operation and input structure to make the full option list meaningful; mechanically padding every question is not a substitute for those tasks.

`dataset_factory.choice_augmentation` provides an opt-in way to reuse a reviewed question with additional impossible choices. It returns a child row and never edits or writes the source row. The child retains the source problem group and split, gets a distinct ID, and carries an augmentation record. The helper requires an exact quote from the context and explicit per-option reasons. Soft augmentation is limited to `exact_derived` and `explicit_stochastic_process` rows whose reviewed, closed-world support exactly matches their nonzero target support. Added options receive exact zero mass in both the target and rational evidence. The helper rejects empirical-frequency and teacher-estimate targets: an unobserved case or a small estimate does not prove impossibility. Hard-label rows require a separately reviewed impossibility proof for every added option.

The proof fields document a claim; they do not make the helper a semantic reviewer. Production use requires a human-reviewed proof. The deterministic-fixture escape hatch exists only for tests. Returned variants carry `mass_training_status: "requires_review"` and should not be added to mass-training files until their source question and proof are reviewed. This repository does not bulk-augment the existing corpus.

After adding options, the helper creates new stable choice IDs and permutes choices, targets, answer indexes, and parallel evidence together. `BalancedTargetSlotSchedule` cycles through every slot for a given cardinality, starting at a seeded phase and using no topic or language input. A 265-choice cycle therefore places positive target mass or a hard answer once in each output position, including index 264. Smaller cardinalities get their own balanced cycle.

An explicit task-grounded “cannot be determined from the supplied information” option is different from a model-confidence abstention. Answerable rows with that option assign it zero target mass; a row whose context entails that no answer is supported assigns the option all target mass. A known stochastic distribution remains answerable: its spread is outcome uncertainty, not missing information. The localized abstention choice counts toward the 265-option limit.

For a separate confidence-based action policy with reward `+1` for a correct answer, penalty `−λ` for a wrong answer, and `0` for abstaining, answering is beneficial only when calibrated correctness probability exceeds `λ / (1 + λ)`. With `λ = 4`, that illustrative threshold is `0.8`; it is not a tuned optimum. Tune and freeze any threshold on a group-safe validation set. Evaluate proper soft-target cross-entropy and Brier score separately from answerability behavior; report answerable coverage, selective risk, unanswerable abstention recall, expected utility, risk–coverage, and always-answer/all-abstain baselines. Never score one task-grounded IDK response simultaneously as a correct answer and as a confidence-policy abstention.

The abstention decision framing follows [Chow (1970)](https://doi.org/10.1109/TIT.1970.1054406) and selective-classification work such as [El-Yaniv and Wiener (2010)](https://jmlr.org/beta/papers/v11/el-yaniv10a.html). Proper probability scoring is covered by [Gneiting and Raftery (2007)](https://doi.org/10.1198/016214506000001437); probability calibration should be checked separately, for example with [Guo et al. (2017)](https://arxiv.org/abs/1706.04599).
