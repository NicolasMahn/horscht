# Soft-target calibration and final evaluation

The last-block experiment uses four group-disjoint splits: `train`, `dev`, `calibration`, and `test`. Assign original problem groups before any choice-order augmentation. Keep every augmented row with its original group and split. Training sees only `train`; checkpoint and stopping decisions use only `dev`; temperature fitting uses only `calibration`; final evaluation uses only `test`.

After training finishes, select and freeze the checkpoint from development results. Run that checkpoint on the calibration rows and fit one positive scalar temperature by minimizing mean categorical cross-entropy against each row's complete target distribution. Do not replace a distribution with its argmax one-hot target. The implementation searches inverse temperature within the recorded bounds (default temperature range `0.05` to `20`) and records when the optimum reaches a bound. Temperature scaling divides every valid-choice logit by the same positive scalar, so it preserves each row's argmax. The 265-choice mask remains in force; only positions `0..count-1` enter the softmax and scores.

Save the selected checkpoint digest, calibration split digest, sorted calibration-ID digest, fitted temperature, search bounds, and aggregate pre/post calibration metrics together. Target rows are validated within `2e-6` of unit mass to accommodate published six-decimal distributions; accepted representation drift is normalized before fitting and scoring. Report mean soft-target cross-entropy in nats and summed categorical Brier score. Also report descriptive confidence summaries: mean, median, and 90th-percentile maximum probability; the fraction of rows above fixed confidence thresholds; mean recorded target mass at the predicted choice; and their mean difference. These confidence comparisons describe agreement with the recorded target distributions. They do not establish empirical calibration or truth when a target is constructed or estimated. Do not present ECE against soft targets as empirical correctness calibration.

Only after the checkpoint and temperature record are frozen, run the final `test` split once. Apply the saved temperature without fitting or changing any setting. The final-test evaluator checks that rows belong to `test` and that the checkpoint digest matches the calibration record. It reports uncalibrated and calibrated metrics from the same logits pass. The aggregate is split into `original_replay`, `fresh`, and each `by_source` cohort so historical test rows do not obscure the result on new source groups. The combined aggregate includes both cohorts; `original_replay` is exploratory. Persist only aggregate metrics; suppress per-row predictions, errors, and target content. The runner writes immutable attempt receipts before inference. A failed or interrupted attempt may be retried only with identical checkpoint, temperature, snapshot, split, and test-ID hashes, and the retry is recorded. Once a final aggregate exists, later calls verify and return it without rerunning inference. If the experiment changes after observing this test, treat the test as observed development evidence and obtain a fresh held-out test for confirmatory claims.

The runner `evaluate_new_training.py` performs checkpoint loading and deterministic calibration/test inference through the training evaluator. It uses the frozen training manifest's token and batch limits, memory reserve, GPU allocation cap, and attention backend. It distinguishes the explicit full-checkpoint and compact trainable-overlay contracts through `backbone_state_kind`; `include_backbone` only indicates that a backbone-state artifact exists. For an overlay it verifies the immutable warm-start base reference and hash, and the shared loader verifies all checkpoint artifact hashes before inference. It accepts frozen snapshots under `data/training_snapshots/` or `data/newtraining/`. Run `uv run python evaluate_new_training.py --stage calibration --snapshot data/training_snapshots/<frozen-snapshot> --run runs/<experiment>/main` first; after `calibration.json` is frozen, run the same command with `--stage test`. If a recovery run selects an earlier best checkpoint, the report may point only to a checkpoint in an earlier `main` or `main-recovery-NNN` sibling within the same experiment directory. The artifact records the active report and manifest hashes, the selected checkpoint path and digest, and the source run manifest hash. The active and source manifests must have the same frozen training contract, with only run identity fields and an audited resource-lifecycle code change allowed to differ. Each stage checks full-input token lengths and builds its deterministic batch plan before allocating the model or doing a forward pass. The default run path is `runs/new-data-last-block-2026-10-08/main`. The pure helpers in `evaluation/temperature_scaling.py` accept CPU or device logits, full target tensors, valid choice counts, row IDs, source cohorts, the complete ID-to-split mapping, and both group IDs per row. They verify that no supplied group crosses splits. They return aggregates and hashes, never row-level scores or identifiers.
