[MMLU-Pro](https://arxiv.org/abs/2406.01574) covers academic knowledge and reasoning across 14 domains, with expanded choice sets up to ten. This complements context-based reasoning with broader subject knowledge; it does not isolate reasoning from recall. The official test parquet is `data/test-00000-of-00001.parquet`. The source schema includes `question_id`, `question`, `options`, `answer_index`, `cot_content`, `category`, and `src`. Gold labels, `cot_content`, and other metadata must never enter model-visible inputs. The official evaluation-code repository uses Apache-2.0, which differs from the data card's MIT declaration; record both accurately rather than applying the code license to the downloaded data. Its code revision was `f418b116db00b065c2aea046518d8fcf74d39872` when checked.

[Belebele](https://arxiv.org/abs/2308.16884) is reading comprehension with a passage, a question, and four choices. The full benchmark has 122 parallel language variants. Five complete language slices provide a manageable initial comparison across English, German, French, Spanish, and simplified Chinese. This is a five-language evaluation, not evidence for all 200 training-language tags. The proposed files are `data/eng_Latn.jsonl`, `data/deu_Latn.jsonl`, `data/fra_Latn.jsonl`, `data/spa_Latn.jsonl`, and `data/zho_Hans.jsonl`. Parallel translations share underlying questions; they are not independent semantic problems. Report language means and account for shared-question groups in uncertainty estimates.

[BIG-Bench Hard](https://arxiv.org/abs/2210.09261) contains 23 reasoning task families. The proposed six files are `bbh/logical_deduction_three_objects.json`, `bbh/logical_deduction_five_objects.json`, `bbh/logical_deduction_seven_objects.json`, `bbh/tracking_shuffled_objects_three_objects.json`, `bbh/tracking_shuffled_objects_five_objects.json`, and `bbh/tracking_shuffled_objects_seven_objects.json`. These use explicit choices and fit the decision interface. They test relational deduction and state tracking. Report them as six selected task slices, not as the full BBH score. Download no few-shot prompt or model-output files. Extract the original question/context and explicit options with deterministic parsing; never infer the answer space from test gold labels.

The adapter must preserve source context and choices without paraphrasing, translating, adding an abstention choice, or rewriting the task. Gold labels remain separate. The 265-output head must mask unused slots before probability normalization. Validate each row's option count, label mapping, input budget, and original option order internally, returning aggregate counts. Never silently truncate away choices. Report length exclusions separately so coverage is visible.

Record accuracy, natural-log negative log likelihood, and multiclass Brier score over valid choices. State whether Brier is the sum of squared class errors and record any numerical clipping used for log loss. Include uniform-choice baselines using each row's actual cardinality; a fixed 25% baseline does not apply across all tasks. Report counts and uncertainty with task/language aggregates. Do not export questions, answers, per-item predictions, error examples, or explanation text to agent-visible reports. Freeze any option-permutation check in advance rather than choosing it after examining results.

These sources provide hard labels. Accuracy tests choosing the accepted answer; log loss and Brier score test confidence against those labels. They do not prove that the model recovers a true non-degenerate outcome-frequency distribution, and they do not test the new abstention semantics. A separate externally sourced probability/answerability suite would be needed for those claims. Do not invent soft targets from hard labels or create unanswerable variants of the blind external test.

Published generative, few-shot, or chain-of-thought benchmark scores use a different interface from a direct classification head. They provide context, not a controlled comparison. A fair experiment should compare methods on the same locked inputs and scoring protocol, and label any format difference explicitly.

Screen the locked benchmark programmatically against the exact known generated training snapshot. Return only aggregate overlap counts and separately quarantine matching training IDs, preserving raw data. Exact and near-duplicate screening can reduce known leakage. It cannot establish absence of semantic overlap, unknown future generator leakage, or exposure during base-model pretraining. Describe the test as independent of this project's fine-tuning corpus, not as guaranteed unseen by the pretrained base model.
